# Aspros.Basic.Framework 2.0.0

## Positioning

`v10` is the Framework architecture/migration line. `2.0.0` is the NuGet SemVer package version.

This release contains intentional source-breaking changes and is the first release boundary for the refactored Framework contract.

## Highlights

- Harden DDD Kernel Entity, ValueObject and AggregateRoot semantics.
- Add Domain Event contracts and transaction-aware dispatch.
- Keep `CommitAsync()` persistence-only.
- Connect Application Pipeline directly to MediatR.
- Add Integration Event publishing through an Application abstraction with CAP available in Infrastructure.
- Add thin gRPC server and typed-client registration helpers for internal microservice communication.
- Keep legacy event and entity contracts available for incremental migration.
- Make AutoInject optional.
- Keep repository/database implementation responsibility in consumer Infrastructure.
- Add Framework tests for transaction rollback, cascading Domain Events, DI and Application Pipeline execution.

## Breaking Changes

### Generic Status type

Removed:

`Aspros.Base.Framework.Domain.Status`

Use:

`Aspros.Base.Framework.Domain.ValueObjects.EntityStatus`

This change avoids a real namespace/type collision with consumer business models that also define `Status`.

### AggregateRoot migration

The new `Aspros.Base.Framework.Domain.Kernel.IAggregateRoot` inherits the legacy empty `IAggregateRoot` contract.

Legacy aggregates do not automatically gain Domain Event behavior. Consumers can migrate individual aggregates to `AggregateRoot<TId>` when they need the new lifecycle.

## Compatibility

Legacy `BaseEntity`, `BasicEntity`, `IEvent`, `IEventHandler`, `IEventBus`, and Infrastructure-facing Unit of Work members remain available for incremental migration.

## Validation

Framework Build/Test was previously verified green before the latest test-only additions. The latest test and documentation commits are intentionally not auto-triggering GitHub Actions because the repository uses low-noise CI.

Consumer validation is manual and must pass against the 2.0.0 package line before a release tag is created.

## Not included

- Generic business RPC abstraction or service registry/discovery implementation.
- Framework-owned User/Category/Trade protobuf contracts.
- Speculative validation/idempotency/observability frameworks.
- Replacement repository abstraction without a demonstrated repeated business need.
